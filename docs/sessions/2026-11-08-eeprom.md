# 2026-11-08 — Cartridge + internal EEPROM (M4 leftover)

## Model (from Swanium's cart/eeprom.rs and bus, the reference)

One 93Cxx device core (`ee_execute` in bus.goose) over a shared
backing store: device 0 = cartridge EEPROM at offset 0, device 1 =
the console's internal EEPROM at offset 2048. A command word is
start bit at bits+2, 2-bit opcode (1 WRITE, 2 READ, 3 ERASE) at
bits, word address below; opcode 0 is the extended group (EWDS /
WRAL / ERAL / EWEN in the 2 bits under the opcode field). Commands
with bits above the start bit set, no start bit, or an out-of-range
word are ignored. WRITE/ERASE/WRAL/ERAL require the write-enable
latch; READ always works and lands in the output latch.

**Cartridge EEPROM** exists only when the ROM footer's save-type
byte (last 16 bytes, offset 0xB) is 0x10 (128 B, 6 addr bits),
0x50 (1024 B, 9 bits) or 0x20 (2048 B, 10 bits): contents start
0xFF-filled and write-LOCKED (EWEN first). Ports: data latch
0xC4/0xC5, command latch 0xC6/0xC7, control/status 0xC8 — a control
write's high nibble selects read (1: execute, latch <- output),
write (2: latch -> input, execute) or command (4: execute only);
the status stores (value & 0xF0) | 0x02 | DONE where DONE is set
only by operations 1 and 8 (the Bandai 2001 errata in Swanium);
reads return 0x02 | DONE. Without an EEPROM the ports read open
bus (0xFF) and writes are ignored. None of the three test ROMs
declares an EEPROM save type, so this path is covered by the new
port-level self-test rather than a test ROM.

**Internal EEPROM**: 2048 B, zero-filled, write-enabled. Data
latch 0xBA/0xBB (reads return the READ output latch, not the
written shadow), command latch 0xBC/0xBD, control 0xBE: 0x10 =
execute + done arrives after one status poll; 0x20 = load the
input latch from 0xBA/0xBB, then execute — except commands whose
byte address is >= 0x60 (the protected system range), which are
refused and set the sticky fault bit (status bit 7) with done
immediately set; 0x40 = execute + done at once; anything else just
clears done. Status reads return 0x02 | done | fault and poll the
read delay. The command width is per-command: bit 12 set means the
10-bit colour form, otherwise the 6-bit mono-compatible form, over
the same storage. Port 0xBF keeps bit 0 as a shadow.

## Left in M4
Only the serial byte protocol (TX/RX bytes, baud timing) — the
TX-ready cause is already modelled. No test asset exercises it.
Save-data persistence (dumping the EEPROM/SRAM contents to files)
belongs with the M5 frontend's file handling.
