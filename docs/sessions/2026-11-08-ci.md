# 2026-11-08 — GitHub Actions CI (modelled on BubiBoyLite)

User: "githubのCIを整備して。bubiboyliteを、参考にして"

## Reference studied

bubio/BubiBoyLite (archived Odin+SDL2 GBC emulator) has three workflows:
build-linux.yml (ubuntu-22.04 amd64 + ubuntu-22.04-arm arm64, mise-pinned
Odin, SDL2 via apt, test-ROM cache, build script with --release --test,
artifact per arch), build-macos.yml (macos-26 arm64 + macos-26-intel,
brew SDL2), and a reusable publish-release-assets.yml that repackages
the raw-binary artifacts into flat zips (binary + LICENSE + README) and
uploads them to the Release. Triggers: push to main with path filters,
PR, release published, workflow_dispatch; concurrency cancels
in-progress runs except for releases; build jobs are contents:read,
only the publish job gets contents:write.

## Adaptations for GooseSwan

- Toolchain: no mise — Goose ships official release tarballs. Pinned
  GOOSE_VERSION=v2026.3, downloaded and sha256-verified in each job
  (linux-x64 06ac30…, macos-arm64 2ffaaf…, macos-x64 3c7f28…).
  There is no linux-arm64 Goose asset, so Linux is amd64-only.
- ubuntu-22.04 kept (glibc floor 22.04+; also runs on Debian 12 /
  MX Linux 23). macOS runners kept (macos-26 / macos-26-intel).
- System deps: nasm (builds the test ROMs) + mesa-vulkan-drivers on
  Linux (lavapipe so the frontend smoke can open a GPU device).
- scripts/ mirrors his layout: fetch_test_roms.sh (FluBBa sources
  pinned by commit: WSHWTest 34e33d5…, WSTimingTest 025e606…;
  byte-identical ROMs to the local goldens — md5 verified),
  fetch_corpus.sh (the 323-file 8086 v1 list embedded, delegating to
  tests/fetch_data.sh), build_linux.sh / build_macos.sh (no --release:
  Goose has no release build mode), run_tests.sh, package_zip.sh
  (binary + README.md; the repo has no LICENSE file).
- run_tests.sh = the local battery: self-tests 39/83/25, corpus
  baseline 634406/646000, WSHWTest Test All, fb_check 3/3, full
  WSTimingTest harvest pinned at 400/7. V20 corpus (9 GB) and the
  WSCpuTest suites (minutes each) are excluded from CI.
- Extra vs BubiBoyLite: a Linux-only frontend smoke step
  (GOOSE_GFX_HEADLESS=1, dummy audio, 300 frames, pixel-exact check).
  Not run on macOS (no GPU guarantee; Goose gfx on macOS is upstream-
  unverified — the macOS jobs still build the frontend and run the
  full harness battery).
- Caches mirror his: tests/roms keyed on fetch_test_roms.sh,
  tests/data keyed on fetch_corpus.sh.

## Local verification (clean copy, official release Goose)

A pristine copy (no corpora/ROMs/binaries) ran the exact workflow
steps: ROM builds md5-identical to the local ROMs; corpus fetch
323 files; build_linux.sh --test -> "all tests passed" in ~80 s;
frontend smoke mismatches=0; package_zip produced the flat zip.
(One local quirk: /tmp on this VM is a 512 MB tmpfs — the sim ran in
~/workspace/ci-sim; irrelevant on real runners.)

.gitignore gained *.sav / *.eep / *.iep (frontend save files).
